# Q-SHIFT — Quantum Error Correction Lab

An offline-first, localhost web demo for exploring the Q-SHIFT Stim/PyMatching research prototype. Historical evidence is shown as a labeled replay; live simulations are generated by the local backend and are never presented as historical or hardware results.

## Windows setup

Prerequisites: Python 3.12 and Node.js/npm. From the repository root, run:

```powershell
Set-Location .\webapp
.\setup_windows.ps1
.\start_qshift_web.ps1
```

The start script builds the React app locally and starts FastAPI at `http://127.0.0.1:8765`. Keep the terminal open while using the app; Ctrl+C stops the local server. No cloud service or external API is used at runtime. To run frontend development mode, use `npm run dev` in one terminal and `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765 --no-proxy-headers` from `webapp` in another.

## What the app does

- **Overview:** Q-SHIFT pipeline, project milestones, and research status.
- **Live simulator:** Runs a real distance-3, five-round Stim Z-memory circuit with the documented synthetic spatial burst, detector-only calibration, and paired Fixed / Estimated / Privileged PyMatching scoring. Each request is capped at 10,000 evaluation shots. The privileged model uses the selected generating probability and is explicitly nondeployable.
- **Syndrome explorer:** Shows detector-bit patterns and observable labels from the latest live request only. Those are generated demo samples, not sealed test data.
- **Research evidence:** Replays committed Stage 4 development summaries, with the audit status and limitations visible.

## Scientific boundaries

The correlated burst is a synthetic stress model. It injects joint X faults on data qubits 8 and 10 after each measurement/reset boundary. It is not a hardware-calibrated crosstalk model. Stim DEM conversion uses the inherited `approximate_disjoint_errors=True` approximation. No quantum hardware is controlled. The Stage 4B results are development evidence, not independent confirmation. The sealed independent test is not included in this app.

The local live simulation estimates burst probability from a separate detector-only calibration batch. The evaluation circuit's generating probability is used only to generate the demo test shots and construct the explicitly privileged reference. Evaluation observable labels are used only for scoring after all predictions have been made.

## Tests

From `webapp`:

```powershell
python -m unittest backend.test_app -v
npm test -- --run
npm run build
```

The backend integration test runs a small real Stim/PyMatching simulation. The frontend tests exercise input validation and metric rendering.
