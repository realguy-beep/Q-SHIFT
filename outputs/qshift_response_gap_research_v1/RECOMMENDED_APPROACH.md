# Recommended controller and decision points

Use a **causal multi-hypothesis selector over a small prebuilt decoder bank**, with independent calibration of the change score and the action margin. Distinguish OFF, previously characterised ON, a nuisance shift and unknown. Accumulate directional evidence if an individual block is ambiguous. When a regime fits and its decoder improves validated risk, switch at the first eligible boundary. Hold the accepted key or use a development-selected pooled static decoder when evidence or risk is ambiguous. Keep ordinary decoding active throughout.

## Smallest defensible implementation

1. **Shared observations.** For each completed block, collect its detector-only marginal vector and a small, development-selected set of parity/cofire statistics. Compute stable-background summaries from eligible older blocks. Use class-specific deterministic masks only after d=5 support checks. Keep the original labelled calibration channel available to every arm for the logically ambiguous flip and record when its labels arrive. Compare a detector-only switching ablation using the same frozen bank. [Q5, Q6, Q9](REFERENCES.md#q-shift-evidence) · [E5, E6](REFERENCES.md#primary-literature)
2. **Separate alarm and identification.** Fit a regularized common-covariance discriminant over the low-dimensional block summaries for each current-state versus alternative pair, including OFF. Fit state means and covariance only on development. Use the pair-specific score as a fitted contrast, and center/scale it on the source-state development distribution. Evaluate a first-look score and Page-style accumulation. Separately require proximity to the proposed state and a best-versus-runner-up margin. Use a small number of frozen looks and empirical calibration at the episode level. A detector tail above threshold is an alarm; only a passing state score and risk comparison name an action. A poor fit to every state means unknown. [E1–E3](REFERENCES.md#primary-literature)
3. **Prebuild bounded actions.** Freeze keys by decoded support/flip, background grid and full decoder settings. Limit the bank to 16 actual keys including robust static fallback. Use the same decoder and model construction as AD3 for a primary within-engine comparison. Prune any action that cannot meet the resource envelope. Give comparable arms the same cache opportunities. Prebuilding known candidate models is permissible only when templates are legitimately available during deployment. Start the recurrent test with no learned episode entries and use the same public candidate-model universe across arms. Treat a development-initialized closed bank as a separate disclosure and contrast it with cold-start recall in an ablation. [Q5, Q6](REFERENCES.md#q-shift-evidence)
4. **Switch based on logical risk.** Freeze a table of paired development losses by state and key. If the next key is favoured and sufficiently supported relative to both held and pooled keys, apply it to future rows. Use upper uncertainty bounds for candidate-minus-fallback loss over the states still plausible at the decision. Calibrate distinct ON and OFF margins. Tune hold or dwell on the development split at matched alarm risk. A missed fast switch still decodes with an explicit fallback. [Risk derivation](MATHEMATICAL_FEASIBILITY.md) · [E9](REFERENCES.md#primary-literature)
5. **Learn unknown states separately.** If the bank rejects the segment, attempt the full causal six-block learner using the original budget. A 2–3-block variant should first pass a development diagnostic that separates background fit, class selection, flip ambiguity and E1T rejection. Use the held or pooled fallback throughout. Accepting fewer flags by itself fails this diagnostic if wrong actions or logical harm increase. Keep all attempts, including “unknown,” in the metrics. [Q2, Q7](REFERENCES.md#q-shift-evidence)

## What success would mean

One block is a defensible engineering and scientific target for recurring or previously characterised states at the current cadence. Realized one-block reliability must be measured against false switches and paired error on unseen episodes. AD3's mixed first/recurrent outcomes and short-history screen provide no evidence that a novel state can routinely be acquired in one block. The preregistered proposal tests returns and first occurrences separately. A closed-bank gain advances the specific known-state result. A gain on unknown support needs a separate open-set result. [Historical decomposition](RESPONSE_GAP_ROOT_CAUSE.md) · [Validation proposal](PREREGISTERED_VALIDATION_PLAN.md)

If calibration or short-window risk fails, the best achievable alternative is to keep the pooled robust static decoder active during ambiguous periods and switch only after strong evidence or a validated full-window estimate. If the fast controller has no logical benefit against that static decoder and AD3, establish whether state changes actually change and improve predictions before adding more sensitive change detection. The next research action is the development-only discrimination and payoff screen in the proposal, subject to a separate execution decision.
