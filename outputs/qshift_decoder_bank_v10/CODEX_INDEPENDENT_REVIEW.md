## Adversarial verification and mandatory fixes

The fixtures use temporary directories and synthetic archives. They never call a Stim sampler. Two process-termination probes passed: interruption with a staged archive preserves it as partial; interruption immediately after the episode rename leaves a valid commit even with a torn worker-event tail and no committed event. The following failure modes reproduced.

| Priority | Reproduction and consequence | Minimum needed before an experimental run |
|---|---|---|
| **Blocker — exclusive start and terminal recovery** | Two concurrent callers using the same valid reservation passed `sp.exists()` in `runkit2.py:210–218`. The losing caller wrote FAILURE and the other completed with ready status. Both logged a start. A fully recovered reservation with no earlier status also admitted a new execution. `_dump:77–83`, `_close_failed:258–276` | Acquire an atomic exclusive start/close claim before mutable output. Reject recovery/failed markers before any job launch. Test two callers, interrupted startup and recovery followed by start. Use process ownership or verified worker quiescence before writing a recovery snapshot. |
| **Blocker — recovery must verify commits** | `inventory` called an empty episode directory committed, although `read_committed` rejected it. Recovery takes liveness on trust. Upstream killed-parent test starts recovery while a worker may still be sleeping, and never checks for a late commit. `runkit2.py:140–194`, `:258–265`, `tests/test_v10.py:80–88,284–300` | Classify only hash-verified commits as committed. Distinguish partial, corrupt and possible sampling. Enforce or verify that no worker can still write and test abrupt supervisor loss. The existing power-loss durability limitation is acceptable if disclosed. |
| **Blocker — analysis admission and semantic evidence** | A ready status with `run_failed` inside the journal and `run_end(state=failed)` was admitted. A record with a nonexistent plausible state, invalid estimator content, negative segment start and invalid length/change points also passed. `validate.py:82–121,145–174` | Enforce one complete successful journal lifecycle, ordered job events and retry/status agreement. Verify the actual approved freeze, training and seed inputs before running. Check base-arm key/source and causal-window metadata against the stated policy, or declare fields diagnostic and keep them out of decisions. |
| **Integration requirement — strict seeds and archive structure** | Fractional seed coercion admitted an alias. The byte validator accepted a ZIP with a duplicate `b06_W0F.npy` entry because it checks set membership. `seed_spec.py:27–44`, `validate.py:124–140` | Validate exact seed types/range/global uniqueness in preflight and reject duplicate archive members. Bind these checks into one actual sampler-free launch through the future study's frozen runner and analyser. |

Other limitations are non-blocking with disclosure. Saved error bits cannot independently replay predictions. Future learned keys cannot all be built in advance. A missing or torn reservation, power loss, and disk failure during cleanup can still require manual diagnosis. The helper should avoid describing an intent marker as a measured draw, but the existing intent marker remains useful for refusing an automatic retry.
