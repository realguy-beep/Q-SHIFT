## Evidence-grounded method notes

### Q-SHIFT-specific internal evidence (historical development only)
The audited strong-fixed-baseline report for the distance-3, five-round, 40-detector/one-observable synthetic pair-X burst setting compares nominal fixed, pooled detector-calibrated fixed, safety-constrained fixed, detector-profile adaptive, and privileged true-p matching on paired final-development arrays. It reports adaptive versus pooled fixed mean LER difference `-0.00002917` over four nonzero burst settings, far smaller than the project's then-stated `0.0002` absolute-LER practical benchmark; the pooled-calibration execution had a disclosed implementation deviation and corrected reconstruction. This is neither clean prospective evidence nor independent confirmation. It implies future work should test whether a prespecified controller can beat a strong static baseline by a policy-relevant margin, not re-demonstrate adaptation versus nominal.

The correlated-noise preflight reports the selected `X8 X10` event yields two-detector DEM records; PyMatching `enable_correlations` true/false had identical 147-edge graphs and identical predictions in a 256-shot plumbing smoke. That result is configuration-specific and is not evidence about untested multi-detector/hypergraph bursts. It does warn that the primary candidate should be mechanism-aware DEM/weights or an explicitly identified graph bank; a correlation flag with no representational change is not a meaningful new decoder arm.

The existing research adapter for BeliefMatching 0.2.0 is disabled by default and separates sampling-circuit identity, generating-noise identity, decoder DEM hash, and assumed-noise provenance. It statically rejects detector-support/observable-signature collisions and repeated targets in decomposed components. These are useful contract safeguards; prior reported deterministic compatibility must not be generalized to arbitrary Q-SHIFT DEMs without matching-model construction and fixture evidence.

Qualitative ranking is by feasibility/value for this specific small Q-SHIFT model, not universal algorithm quality. No candidate's logical performance has been newly measured in this research phase.

**Primary source implementation inspection:** The existing source-faithful burst-profile estimator is a batch feature-template fit on 45 binary features (40 detectors plus five burst-pair co-firing features), known development p-knot labels, pooled SD scaling, linear interpolation and a 1e-5 uniform p search grid. It holds all non-burst generator settings fixed. Its input at estimation is detectors only. It is not a joint burst/measurement fit and not a streaming trigger. `headroom.py` has a separate marginal-only composite score, which should not be conflated with the 45-feature estimator. The generic causal selector exists separately and is not connected in the reviewed source to the profile estimator plus chronological sliding window.

**Decoder-family prioritization:** the paper-level advantage of BeliefMatching derives from BP-informed handling of circuit-noise correlations and cross-sector structure; BP+OSD/BP+LSD target qLDPC/hypergraph decoding; tensor networks trade generality for contraction cost; UF targets efficient graph decoding. Q-SHIFT's current selected burst is a graphlike pair edge and its on/off PM correlation-flag smoke was identical, so none has a demonstrated distinct information advantage on the current narrow setting. A future decoder arm should be added only after a deterministic DEM/fixture gap is established and the exact model information is parity-controlled.

### Static computational envelope of the existing estimator (no runtime benchmark)
The existing estimator uses a uniform probability grid whose bounds are the minimum/maximum template p knots. The inspected feasibility config declares template knots `[0.002, 0.01, 0.018]`; with 1e-5 step, the estimator grid has 1,601 points. A dense float64 expected-feature grid for 45 features is `1,601 × 45 × 8 = 576,360` bytes (~0.550 MiB), excluding Python/NumPy overhead. A score vector adds 12,808 bytes. This is a bounded profile-fit computation if expected grid means are cached. The current source recomputes interpolation/score arrays per estimate, so a cached immutable mean grid is a plausible semantics-preserving optimization for future implementation (not changed or benchmarked here).

However, a 1,601-point *parameter search* does not imply a 2,001-decoder graph bank. Building/caching 2,001 Stim DEM + PyMatching objects could dominate startup and memory. Separate the fine parameter estimator grid from a smaller, predeclared set of graph nodes; map estimates to that bank via a frozen rule, and account for construction amortized over a prespecified deployment horizon. A graph bank's size, quantization, switch threshold, horizon and acceptable inference overhead are unresolved owner/protocol choices. No empirical runtime or memory claim is made.

The profile objective uses per-feature SD scaling and sums squared residuals, which corresponds to a diagonal metric. Pair features share detector bits and all features are shot-level correlated; treating the diagonal score as a full likelihood or as independent feature evidence is unjustified. Full covariance weighting would require finite-window covariance estimation/regularization and could be unstable when the number of effective history shots is small relative to 45 dimensions. It should remain a sensitivity comparator, not an assumed improvement.



**BeliefMatching feasibility note:** The official implementation (commit already pinned locally to `4458c278bbec273c8c1a26411dadccc49222f8ef`, package 0.2.0, Apache-2.0) accepts circuit or decomposed DEM; the README says decomposed DEM is required for DEM input. It runs full-DEM BP and constructs a new PyMatching instance per shot; upstream explicitly cautions it is not performance-optimized. This is a decoder integration/throughput risk, not a correctness rejection. Its potential value is strongest for hyperedge information absent in MWPM; selected Q-SHIFT pair-X event is graphlike, so no current reason to include it in an adaptive controller study unless a distinct representation advantage is proven.

**Feature-map scope calculation:** 40 detector bits provide all 40 one-detector marginal means. The five additional cofire coordinates are five selected two-detector joint probabilities; from these and their marginals one can recover five corresponding pairwise correlations. There are `C(40,2)=780` possible detector pairs, so the map captures 5/780 ≈ 0.641% of all pair identities and no explicit three-way-or-higher moments. (This percentage describes pair-index coverage, not information fraction.) The compact feature map is tailored to five known burst boundaries and cannot serve as general syndrome-correlation characterization. Any new correlation pattern can fall entirely outside the selected pair set.

## Provisional ordered research priorities (not an experimental authorization)

1. **Causal detector-profile controller with a predeclared mismatch/fallback guard** — best fit to the current Q-SHIFT question and existing source; only low-dimensional burst p is supported by its fixed-measurement template family. Deterministic exact categorical means now show rank-2 burst/measurement local sensitivity and no collisions on an 81-point coarse grid; a burst-only population fit is biased by about 0.002 under the explored measurement/gate mismatch. Before any finite-history study, specify and deterministically assess the residual/fallback guard and false-alarm target, then define shot/round time and equal-history static/trailing/EWMA/periodic baselines. Potential contribution is policy/safety evidence, not a new decoder algorithm.
2. **Simple periodic and trailing-window/EWMA recalibration baselines** — required controls, easier to specify, likely lower false-alarm complexity. They may match or exceed event triggers; no reason to assume a more complex change detector is needed.
3. **DGR-style matching-history updates** — direct literature route for correlated drift but pseudo-label self-dependence and potentially large data needs make it secondary. Would need a conservative update guard and explicit unknown-noise same-information comparison.
4. **BeliefMatching / correlation-aware decoder** — scientifically test only where model representation includes hyperedges or non-graphlike correlations that ordinary PM discards. For current graphlike selected burst, no demonstrated extra representation. Existing Q-SHIFT adapter checks input semantics but official code has per-shot BP and new matcher construction.
5. **Bayesian tensor-network + MCMC/SMC** — strongest model-based parameter uncertainty route for rich known channels, but its stochastic posterior inference and likelihood costs are inappropriate for first deployable implementation and outside current constraints. Could be a later offline reference.
6. **Neural continual decoder / residual model** — QAdapt v2 (10 Nov 2026) reports a 650,332-parameter supervised predecoder with paired d=9 and Willow/compound-noise evaluations, but one realized training seed per configuration and different noise/objective. It is relevant if supervised pretraining is authorized, not a drop-in detector-only graph controller. Q-SHIFT's existing strong baseline evidence does not justify restarting training.
7. **BP+OSD/LSD, union-find, tensor-network decoding** — useful for other structure/latency regimes; no current Q-SHIFT representation or scalability need justifies adding them before causal adaptation is understood.

**Provisional readiness:** GO for bounded deterministic protocol and model-adequacy design; HOLD for any new stochastic development study or implementation claims until exact causal stream semantics, measurement-mismatch identifiability, graph-bank size/cost, and static-baseline tuning budget are frozen. No sampling approval is implied.

### Checkpoint 122 update — method ranking and novelty boundary

The former statement that the scalar trigger requires fixed gate p `.003` is superseded for the balanced exact categorical model when a physical gate interval `[.002,.004]` is accepted as an enforceable null/alternative nuisance range. A three-parameter rational Bernstein certificate plus a bounded-statistic log-chord argument now gives continuous positive up/down population log growth without an online gate estimate. This moves the **alarm statistic design** ahead of general profile fitting as the best-specified deterministic trigger candidate. It does not move adaptive graph switching above strong static/trailing/EWMA comparators: no detector histories, switch policies, false-alarm/false-switch rates, or logical outcomes were generated.

The 45-feature exact-circuit and approximate-DEM Jacobians both have local numerical rank 3 at the nominal point; their singular spectra and nearby profile distances are very similar. This updates the earlier two-parameter identifiability concern for the stated three-parameter family, but the nearest profile distances are small and neither result predicts finite-history precision. It also does not resolve physical attribution: the mean e-factor avoids attribution by taking a worst-case gate envelope. The narrow research contribution, if later supported, would be a bounded nuisance-aware alarm-to-cached-graph policy for this known pair-burst family, with equal-information recalibration controls. Broad detector-driven adaptation, learned edge weights, and neural decoder adaptation are already established neighboring ideas; no broad novelty claim is supported.

Remaining order: (1) resolve whether the gate interval is physically defensible and validate an outward-safe implementation; (2) prespecify dead-band/state/reset and repeated-switch alpha allocation; (3) compare the trigger with same-history trailing, EWMA and periodic baselines; (4) only then request a bounded development study of graph selection utility against strong static matching. Approximate-DEM continuous envelope transfer and all decoder-benefit claims remain open.

**Checkpoint 124 transfer warning:** a 250-point approximate-DEM screen found one high-alternative mean below the exact-circuit lower envelope at `(.010,.001,.002)` by `5.9848e-8`. The DEM grid still separates low and high regimes, but the exact-circuit constants are not a valid DEM guarantee. Treat circuit and DEM e-factor arms as separate model identities; a future DEM alarm requires its own continuous envelope or a conservative transfer proof.

The exact-circuit result remains applicable if monitored detector vectors are generated by the exact categorical circuit; choosing an approximate DEM for downstream graph construction does not alter that data law. The transfer failure only prohibits using the DEM as a substitute source distribution for the e-factor proof.

**Checkpoint 126 state-machine hold:** the directional e-factors have different nulls. A false low-to-high alarm makes the opposite high-null process invalid unless a separate state-recovery mechanism reestablishes that null. Reset-count alpha allocation alone is insufficient for repeated switches. Keep the feasible disposition at “alarm statistic candidate”; do not call the bidirectional controller ready.

**Provisional publication potential:** Broad “adaptive QEC decoding” is already well covered (algebraic adaptive weights, GP tracking, DGR, syndrome-moment drift estimation, Bayesian SMC, and neural continual learning). A publication would need a narrower defensible contribution: causal event-triggered switching from detector-only summaries under the known-support per-boundary Bernoulli X8/X10 pair-burst family embedded in the circuit's categorical baseline gate noise, explicit nuisance-confounding/fallback behavior, and fair root-clustered comparisons against strong static plus simple recalibration methods, with costs and negative results preserved. A distance-3 synthetic result alone is likely insufficient for broad generalization or strong novelty claims; evidence across independent code/noise families or hardware relevance would matter. This is a literature-based preliminary judgment, not an acceptance prediction.

**BeliefMatching nuance:** when BP converges, upstream returns a BP-derived observable estimate; when it fails, it uses per-shot BP-weighted matching with a newly constructed PyMatching graph and virtual boundaries. Future deterministic checks should record which path occurred; performance comparisons must include construction and per-shot costs. Same DEM source is fair information provenance, although the effective representation differs by algorithm.

### Historical estimator evidence and scope
`outputs/stage4_noise_adaptive_feasibility_v1/STAGE4_FEASIBILITY_PILOT_FINDINGS.md` reports fixed-measurement detector-only p-estimation at two unseen p values with three independent roots per value; errors vs nominal improved in that small paired development run. The later strong-fixed report shows near equality to pooled static, so the earlier nominal contrast is not the right effect for an adaptive-benefit claim. Full figures/limitations and numbers are recorded in the dated checkpoint-6 log entry. Do not recast the six-root pilot as confirmatory.

**Profile estimator failure-mode review:** The current `estimate()` API returns only the minimizer p, never the best-fit residual, interval, or OOD/abstention state. It forces a p within `[0.002,0.018]`, so a measurement/gate/correlation mismatch is silently projected onto the burst profile. The fifth feature set could offer partial mismatch sensitivity, but no predeclared residual guard or calibration exists. Bootstrap is resampling shots from a given batch with fixed template profiles; it is not a coverage result and does not incorporate template uncertainty/temporal dependence.



### Literature-based limitations added at checkpoint 10
A detector-model residual can serve at least two conceptually distinct roles: a distribution-compatibility score for ranking or rejecting individual records, and a population-level feature discrepancy used as an alarm for parameter estimation. Recent primary work on MWPM minimum-cost postselection addresses the first role. It neither establishes the second role's identifiability nor shows that adaptation improves unconditional LER. If Q-SHIFT cannot reject shots, its objective must remain unconditional decoder error; any postselection arm needs accepted-yield and rejection-budget accounting and should be treated as a distinct product objective.

The literature ranking therefore keeps the simplest parametric causal controller as a *conditional* next hypothesis only after deterministic identifiability/model-adequacy work. It is not ranked above prior art as an algorithm, and no measured Q-SHIFT advantage is claimed.

### Score bases and confidence
- **Strong static PyMatching:** Local development protocols/report establish a finite candidate selected with separate development selection/validation, same held-out development detector/observable arrays as other arms, low inference complexity and a much stronger comparator than nominal. Confidence is medium because the later pooled calibration run had a disclosed implementation deviation and corrected reconstruction; scores do not imply a globally optimal static decoder.
- **Profile + causal trigger:** Repository source directly supports a small detector-only 45-feature burst profile and a separate causal selector, but not a wired streaming policy. No causal switch performance has been measured; measurement/gate mismatch and exact identifiability remain open. Low-to-medium confidence.
- **Trailing/EWMA/periodic:** Established low-complexity sequential baselines; Q-SHIFT has no matched evaluation. Their analysis is causally implementable with prior detector histories, but finite-history false-alarm/adaptation behavior for dependent 45-vectors is uncalibrated. Medium confidence for feasibility, low for benefit.
- **DGR:** Primary paper describes match-count pseudo-observations, subsequent reweighting and a learned/heuristic correlation stage. This is causally possible but feedback-endogenous and potentially data-hungry; no Q-SHIFT implementation/API audit was performed. Low-to-medium confidence.
- **Bayesian TN/SMC:** Peer-reviewed model-based syndrome inference provides parameter uncertainty when the generative family is specified; the paper also reports weak sensitivity for some parameters. Q-SHIFT categorical burst + measurement nuisance fit, online cost and small-history behavior are unestablished. Low confidence for this architecture.
- **Compatibility/postselection:** Primary 2026 work reports hardware and controlled-model evidence that minimum cost adds mismatch information beyond logical gap; however the operational effect is conditional postselection with acceptance/yield accounting. It cannot be substituted for unconditional LER improvement or parameter attribution. Medium confidence in adjacency, low in Q-SHIFT transfer.
- **BeliefMatching:** Pinned Apache-2.0 implementation and NS-3B adapter are present; deterministic compatibility evidence exists in a separate research package, but Q-SHIFT's selected pair event is graphlike and prior correlation-flag PM smoke showed no distinct result. Native BP plus per-shot matching construction is a cost risk. Medium confidence in basic integration; low in performance opportunity.
- **BP+OSD/LSD:** Strong published hypergraph/qLDPC use cases, but no identified non-graphlike information gap in the current selected Q-SHIFT burst arm. OSD/LSD cost and d=3 relevance are not measured here. Medium confidence in literature evidence, low in fit.
- **FiLM:** Peer-reviewed PRResearch hardware evidence; uses calibration telemetry and supervised correction targets and is trained separately per code configuration. Q-SHIFT lacks this input/training scope and is a different code family, so architecture compatibility is low despite paper evidence. Medium confidence.

No score represents observed Q-SHIFT performance. No weighted total is a statistical estimate. The most justified current action remains deterministic identifiability/model-adequacy work; an experiment remains unauthorized.
