## Source-faithful Q-SHIFT estimator inspection

### Additional decoder modalities reviewed at checkpoint 14

| Family | Required information | Relationship to current Q-SHIFT | Working disposition |
|---|---|---|---|
| Analog/soft readout decoder | Raw readout likelihoods or analog outcomes, calibrated observation model | Current interface contains binary detector events only; hardening discards the signal these methods exploit | Out of current scope; revisit only if source data contract expands |
| Leakage-aware decoder/adaptation | Leakage flags or a physical leakage-state model; often hardware-trigger signals | Leakage is not part of the declared burst mechanism; no current detector-only identifiability claim | Separate noise-model extension, not a baseline for this study |
| Harmonized decoder ensemble | Multiple decoder outputs and a model/tuning policy | May improve static decoding and thus strengthen the comparator; does not estimate burst state | Consider a bounded deterministic construction/runtime audit before study design; no Q-SHIFT benefit assumed |
| Renormalization-group decoder | Code geometry and a coarse-graining/free-energy inference implementation | Feasible algorithm family, but no demonstrated advantage on the current small graphlike circuit | Lower priority than establishing information parity and a strong PyMatching comparator |
| Recurrent/transformer or state-space decoder | Sequential syndrome records and supervised logical targets for training; recurrent state for long streams | Solves per-shot logical prediction; Q-SHIFT controller instead estimates burst drift to select cached graph priors | Adjacent high-complexity paradigm; not the immediate detector-only controller baseline |
| DFR-based logical-risk monitor with remapping (ReloQate) | Recent detector-fire history plus calibrated DFR-to-LER relation; spare patches and remapping operations | Responds to predicted system-level risk by moving a logical patch, not by estimating a physical burst p or changing matching weights | Relevant systems context; different actuator and hardware assumptions |
| Learned syndrome-statistics edge/hyperedge calibration (Chamberland et al. 2026) | Two consecutive bulk syndrome rounds, a trained 25-parameter noise model, and circuit-family-specific edge/hyperedge formulas | Directly estimates matching-relevant probabilities in batches; not a low-dimensional causal burst estimator; assumes the paper's standard rotated-surface-code mechanisms | Important prior art; high training/data/GPU cost and model mismatch make it non-drop-in for Q-SHIFT |

`outputs/stage4_noise_adaptive_feasibility_v1/prototype.py` contains `detector_features` and `DetectorProfileEstimator`:

- Feature row: 40 detector bits plus five pair co-firing bits `(D8&D10)`, `(D16&D18)`, `(D24&D26)`, `(D32&D34)`, `(D36&D38)`.
- Template fit: group simulator development template batches by supplied burst p; compute feature means at sorted p knots; coordinate scales are pooled SD floored at `sqrt(1e-6)`.
- Inference: compute batch feature means from detector-only input; linearly interpolate template means over a uniform p grid at step `1e-5`; choose p minimizing mean squared standardized coordinate residual, NumPy first-index tie behavior.
- This estimates the synthetic burst-probability parameter only. Gate/meas probabilities are fixed by the profile builder; it does not jointly fit them. The estimator does not itself perform streaming/causal change detection; it consumes an externally selected finite detector batch.

Separate `outputs/headroom_feasibility/headroom.py` code has smoothed detector marginal profiles and a summed independent-Bernoulli composite log score. That is a different fit method; it omits pair co-firing correlations. Do not describe this marginal score as the 45-feature prototype.

`qshift_core_v1/controller.py` supplies a generic selector that validates `based_on_through_block < current_block`, requires detector-only estimate provenance, and implements confidence/hysteresis/dwell/fallback logic. No wiring from the 45-feature profile estimator into this generic causal selector was found in the reviewed files. Historical Phase 4A/4B/4C and strong-fixed runs are batch-calibrated or per-root-calibration policies, not causal adaptation during the chronological scored stream.

## Common information-set and time-axis contract for any later study

The methods in the literature operate on different time axes, so their “online” labels are not interchangeable:

| Policy family | Learning / adaptation data | Time axis / update | Labels during adaptation? |
|---|---|---|---|
| Q-SHIFT profile estimator in `stage4_noise_adaptive_feasibility_v1/prototype.py` | Labeled synthetic p-knot templates for fit; detector-only calibration batch at estimate time | Batch probability estimate; no rolling update inside source | No logical labels at estimate time; template p labels are development-time metadata |
| Q-SHIFT generic selector in `qshift_core_v1/controller.py` | `SelectionProposal` plus detector-only `NoiseEstimate` with prior block provenance | Block selection with confidence/hysteresis/dwell; not wired to a stream estimator in the inspected code | No; it requires detector-only provenance |
| Bhardwaj et al. sliding/relative window | Syndrome statistics under the assumed graph-edge Pauli model | Rate estimates vary with syndrome extraction cycles / windows | No logical labels in the stated estimation method |
| Spitz et al. / Huo-Li | Syndrome / correction statistics from past QEC cycles; model-specific estimator/predictor | Repeated rounds in an ongoing QEC process | Uses correction predictions/statistics, not future logical labels; assumptions differ |
| DGR | Prior MWPM matching outputs and inferred edge co-occurrences | Previous decoded trials; periodic/event-triggered reweight then decode future trials | No ground-truth labels required online, but matching outputs are pseudo-labels |
| QAdapt | Simulated correction-target training examples, task sequence, EWC state | Training across noise tasks, then frozen transfer/evaluation | Yes, correction targets during training; not online labels at final inference |
| Bayesian TN + SMC | Syndrome likelihood under specified physical channel and circuit | Sequential parameter posterior over observations | No logical labels, but model-specific likelihood and Monte Carlo inference |
| Static selector / calibrated bank | Separate calibration and selection-development datasets | One-time frozen model selection | Logical labels can select a fixed decoder in development only; none flow into deployment estimates |

**Q-SHIFT proposed time unit must be explicit:** prior proposals talk about chronological completed shots/root blocks. The cited sliding-window papers often model changing rates across rounds of an ongoing memory. A five-round shot is a *single* circuit execution containing an internally ordered syndrome sequence; updating after each completed shot cannot use later rounds from a different shot as if they were contiguous rounds in one uninterrupted memory unless the physical experiment semantics justify that concatenation. The adaptation target should be written as either (a) drift across independently reset shots, with one detector vector per completed shot and update only before the next shot, or (b) drift within a continuing memory stream with round-level causal syndrome decoding. Q-SHIFT's current distance-3 five-round circuit evidence supports the former synthetic use; it does not establish the latter hardware workflow.

**Fair later comparison:** freeze a single feature map, detector history, candidate model bank, calibration/template budget and graph-cache opportunity. Fit policies on prior eligible development data, then run fixed, pooled-static, trailing-window, EWMA, periodic, and event-triggered policies causally on identical fresh development streams. The controller may inspect current detector bits only after the current shot's prediction is finalized, then change cached decoder only for the next shot. Keep all labels/observables sequestered until every prediction and switch decision is immutable. The privileged true-p decoder remains a separate upper-reference arm. A DGR-style policy must use its own previous decoder outputs and be identified as such, not mislabeled as detector-profile estimation.

### Circuit-time versus stream-time from actual source
Static reading of `outputs/phase3a_correlated_noise_preflight/simulator.py::build_spatial_burst_circuit` confirms the burst parameter is inserted as `CORRELATED_ERROR(p) X8 X10` after each `MR` boundary. There are five boundaries in the five-round circuit; the five events are independent across rounds, and each event is spatially joint across the two data qubits. The builder preserves detector/observable definitions.

This defines an intra-shot stochastic process with five independent possible burst events conditional on a constant configured p for that circuit execution. A separate controller chronology would be across completed circuit executions/shots; that controller cannot observe the five within-shot detector outcomes until its output prediction for that shot is already fixed. A future drift schedule must state whether p is constant across all five internal boundaries of each shot and changes between shots, or changes boundary-by-boundary within a shot. Those are different simulators/estimands. The existing code supports the former by building one circuit at one p; it does not implement within-shot drift. Do not present the sliding-window literature as directly matched until that time-index mapping is specified.

A same DEM hash is good provenance parity, but an algorithm that can use hyperedges has a different representational capacity than graph-only MWPM. State both facts.

### Mismatch and uncertainty behavior from source (static inspection)
`DetectorProfileEstimator.estimate()` returns a scalar p only. It computes minimum diagonal-standardized feature distance on the configured interval but does not return the minimized residual, parameter uncertainty, confidence/coverage, out-of-template alarm, or abstention/fallback decision. Therefore any detector batch—including one generated by changed measurement p, gate model, burst geometry, or a mixture not represented by templates—gets forced to a p estimate. A later controller must separately define model-adequacy residual limits and conservative fallback; it must not call a low fit residual a calibrated probability or use the estimator's point value as evidence that its model is adequate.

The estimator's per-feature `scales` come from pooled template variance with a floor, but no cross-feature covariance enters the objective. Detector and pair-cofire features share detector bits and are dependent within each shot; diagonal scaling is a pragmatic composite score, not an independent-feature likelihood. Its bootstrap resamples shots from a calibration batch and conditions on the fitted templates; it does not account for template-bank uncertainty or unmodeled serial dependence/drift. Historical bootstrap intervals were explicitly described as diagnostic and not coverage claims.

**Measurement-mismatch implication:** because the template family fixes p_meas and p_gate, changes in those directions can be confounded with p_burst if their 45-feature mean shifts align. Residual patterns may reveal some mismatch, but no calibrated guard exists in the estimator. The existing pilot's p interpolation at matched measurement/gate settings cannot validate measurement robustness. Prior deterministic joint-estimator review should be revisited for quantitative population mismatch evidence before selecting a guard statistic.

### Three noise/model layers that must not be collapsed

1. **Categorical circuit distribution:** Stim circuit has balanced categorical Pauli-channel gate noise plus measurement noise and a separately injected correlated X8X10 event at five boundaries. This is the generating distribution for the current synthetic development model. At fixed settings, a single p parameter is shared across five independent boundary-event opportunities per shot.
2. **Detector feature/template distribution:** the estimator sees finite empirical means of 45 features from development templates at three known p settings and linearly interpolates. It does not know the full detector-vector likelihood. Template means and diagonally pooled scales have estimation error; linearly interpolated means are only an approximation between knots.
3. **Approximate DEM/decoder distribution:** decoder construction converts Stim's model with `decompose_errors=True, approximate_disjoint_errors=True`, then PyMatching or BeliefMatching applies its own graph/factor-graph interpretation. Approximate handling of disjoint categorical mechanisms can differ from exact circuit outcome probabilities. The burst itself has graphlike support for the selected pair, but the base categorical mechanisms may decompose.

Thus a profile p estimate can be evaluated against true circuit p, but that is not a proof that the fitted feature profile is a correct DEM likelihood or that the resulting graph minimizes finite-circuit LER. Report source circuit identity, template profile identity and decoder DEM identity separately. More elaborate decoders may exploit mechanisms lost or approximated in the DEM; comparisons should disclose that model representation difference rather than credit all result differences to an algorithm alone.

### Statistical geometry for measurement-mismatch guarding (design only)
For a fixed measurement probability, the 45-feature template means trace a one-dimensional curve `μ(p_burst)` in feature space. A detector-only measurement mismatch changes the mean to a point `μ(p_burst,p_meas≠p0)`; the current profile estimator projects it onto the fixed-p_meas curve and returns the closest p. If the mismatch displacement has a component orthogonal to the burst curve under the declared metric, a model-adequacy residual could flag it. If the nuisance displacement is parallel/tangent to the burst curve, this feature map cannot separate causes locally; any scalar residual guard will miss the alias. A joint Jacobian/singular-value/profile-collision analysis is needed before claiming a safe trigger, and must use the exact feature map plus explicitly labeled DEM-vs-circuit expectations. The 45-feature code itself does not expose the residual or compute this check.

A change trigger based only on the scalar p-hat can also misinterpret orthogonal measurement/gate drift as burst drift. The safer design would monitor a vector of standardized feature residuals, estimate only when the profile remains adequate, and otherwise return the fixed fallback. This is a hypothesis for deterministic model-adequacy design; no numerical Jacobian or simulation was performed here.
