# HAMLD implementation and Q-SHIFT compatibility

## Version and source reviewed

Pinned upstream repository `kechen666/hamld` at main HEAD observed on 2026-11-12: **`b80c627220773c5b8371fc2753ddf2d4d3773a10`**. This pin is used for every source observation below; it is not a validated release. The Apache-2.0 license is present. Reviewed `README.md`, `pyproject.toml`, `src/hamld/__init__.py`, `src/hamld/hamld.py`, `src/hamld/contraction_strategy/dem_to_hypergraph.py`, `src/hamld/contraction_strategy/contraction_strategy.py`, `tests/README.md`, tests/notebooks, and `tutorial/HAMLD_Tutorial.ipynb`. The README/tutorial are examples, not evidence that the package accepts every Stim DEM representation.

## Input and inference semantics

- Public Python constructor accepts a `stim.DetectorErrorModel`; the documented path calls `circuit.detector_error_model(decompose_errors=False, flatten_loops=True)`. The interface is DEM-based, not raw circuit or detector-sample based.
- `HAMLD.decode_batch` consumes detector-only syndrome rows and declares result shape `(batch, num_observables)` with Boolean predictions. The single-syndrome API returns a prediction, logical probability distribution and confidence-like value.
- The code builds a hypergraph from DEM `error` instructions and contracts the graph using detector order / selected slice and approximation strategy. Its objective is logical-class likelihood/degeneracy aggregation (approximate MLD), rather than MWPM’s minimum sum-weight correction. Exactness depends on graph representation and contraction/truncation settings; the API exposes order (`mld`/`greedy`), slice strategy, numeric precision, lookup, `use_approx`, approximation strategy/parameter and alternative executors.
- In `dem_to_hypergraph.py`, each `error` instruction's targets are traversed; detector and logical targets are kept, while other target types are skipped. `^` separator tokens are not interpreted as alternative decompositions: the targets from all components are put in one hyperedge. The converter only iterates top-level `error` instructions; nested repeat/shift behavior is not implemented explicitly. For Q-SHIFT's already flattened Stim circuit, the resulting DEM has no repeat/shift instructions.
- The source converter stores the `error(p)` value as a `Decimal` weight. The normal Python contraction executor treats this value as an independent Bernoulli probability (`p` and `1-p` branches), not as a matching log-odds weight. Q-SHIFT's undecomposed DEM error target signatures had no duplicates at p=0 or .01 (443/443 and 448/448 unique), so the dictionary overwrite issue is not present for those observed DEMs. Recheck for every profile before use.
- Multiple detector counts are read and detector IDs are represented directly. `decode_batch` allocates `(batch,num_observables)`, but the normal Python `validate_logical_operator` explicitly requires exactly two logical-class keys and compares only the final bit. Thus the one-observable Q-SHIFT case is the only source-supported form established here; multiple-observable behavior is not supported by that path. D-only boundary mechanisms are representable as one-detector hyperedges, but their prediction behavior was not executable here.
- The default documented/examples use `decompose_errors=False`; Q-SHIFT’s established PyMatching DEM uses `decompose_errors=True, approximate_disjoint_errors=True`. The raw undecomposed Q-SHIFT DEM still has detector hyperedges up to degree four and no separators; the decomposed form contains many separators. Passing the latter to this parser merges separator components into one event; passing the former avoids that particular issue but changes the decoder’s modeled mechanism set and does not repair any approximation in the DEM itself.

## Logical and boundary mapping

The source represents detector nodes `D0...D(n−1)` and logical nodes `L0...`; its normal Python validator returns whether the higher-probability of two logical classes is L0=True. This is a predicted observable-error bit, not a physical Pauli recovery operator. The deterministic local Stim/hand-case checks establish Q-SHIFT's expected detector and observable dimensions and target IDs, but HAMLD's output convention was not executed. Boundary, zero-syndrome and single-fault output mapping remain unverified until the package can run.

HAMLD receives no raw measurement record or separate data-qubit readout channel: it sees the DEM and detector syndrome. Q-SHIFT's terminal data measurements are already reflected in its Stim detector definitions and `OBSERVABLE_INCLUDE(0)` mask. Whether HAMLD preserves that boundary/readout mapping still needs deterministic output tests. The paper's warning that its surface-code gain is limited when data-qubit measurement syndromes are available does not establish either benefit or failure for Q-SHIFT's terminal-readout detector model.

Accuracy-affecting controls include `use_approx`, its strategy and truncation parameter, contraction order/selection strategy, float precision (`float64` versus decimal/other paths), slicing strategy and lookup behavior. The source's default Python `normal` path has `use_approx=False`; approximate strategies can drop probability-state terms according to strategy and parameter. No Q-SHIFT setting can be selected scientifically until exact input semantics and deterministic outputs are verified.

## Build, resource and applicability

The current Python package declares `>=3.10,<3.11`; the available runtime is Python 3.12.10. `src/hamld/__init__.py` imports `hamld_pybind11` unconditionally, but no built extension is present in the published source tree. The repository instructions require Bazel 8.2.1 plus manually cloned C++ dependencies; Bazel was not available. We did not install/build the package. The README recommends Linux with ample CPU and memory, but gives no applicable Q-SHIFT r=5 resource bound. The paper reports a d=3, r=3 result (optimal accuracy; about 323× faster than its MLD baseline and 551× faster than TN-MLD) and its surface-code comparisons are at its own code/noise/measurement settings. It does not establish a five-round Q-SHIFT advantage. No runtime, RAM, or LER performance number is claimed here.

## Decision

**FIX before any HAMLD comparison; do not sample yet.** The pinned parser cannot safely consume Q-SHIFT's *decomposed PyMatching DEM*: 444 of its 586 nominal error instructions have separators, which the parser merges into a single hyperedge. A plausible route is to give HAMLD a separately generated *undecomposed* Stim DEM (`decompose_errors=False, approximate_disjoint_errors=True`, no repeat blocks), which has degree-4 hyperedges and unique signatures; the source's hypergraph implementation appears intended to process such hyperedges. This is not yet a demonstrated integration: categorical `PAULI_CHANNEL_2` still requires Stim's disjoint-error approximation, decoder output mapping was not executed, and Python/build prerequisites block runtime tests. Before reconsidering a pilot, pin and build an eligible environment, prove the undecomposed DEM is preserved by the HAMLD parser, test p weights and zero/single/boundary/logical cases, and report the different HAMLD vs PyMatching DEM transformations without calling them identical models. Do not flatten separator targets or silently claim the decomposed and undecomposed DEMs are interchangeable.
