# Reproduction and evidence boundaries

Run from the repository root with the existing Python environment. No dependency installation is needed.

```powershell
python outputs/stage5_design_validation_v1/prepare_seed_inventory.py
python outputs/stage5_design_validation_v1/test_dynamic_audit.py
python outputs/stage5_design_validation_v1/test_seed_inventory.py
python outputs/stage5_design_validation_v1/freeze_candidate.py
python outputs/stage5_design_validation_v1/design_simulation.py
python outputs/stage5_design_validation_v1/pipeline_benchmark.py --limit-new-roots 7
python outputs/stage5_design_validation_v1/pipeline_benchmark.py
python outputs/stage5_design_validation_v1/audit_dynamic.py outputs/stage5_design_validation_v1/benchmark_run
```

The sequence above records what was executed. `freeze_candidate.py` creates a pre-run source/configuration hash freeze; in a reproduction, verify and preserve that freeze before running. The benchmark writes disposable `.npz` arrays only to `stage5_design_validation_v1/benchmark_run/roots/`; do not copy them into Stage 5 or use their outcome metrics as confirmation. The resume test intentionally pauses after seven roots, then validates existing checkpoint hashes before generating the remainder.

`DESIGN_SIMULATION_RESULTS.json` contains synthetic root-effect draws only, not detector/observable samples. `BENCHMARK_AUDIT.json` is independently generated by `audit_dynamic.py` and verifies paired predictions from saved arrays. The frozen v2 Stage 5 runner was never invoked. No Stage 5 evaluation shots were generated and no sealed historical test path was read.

For a new validation run, create a new versioned output directory and new collision-screened seeds; do not rerun over or replace the retained benchmark archives.
