## Executive findings

1. The repository has no verified result establishing 99.99% logical correction success. The only local source occurrence matching the reported “99.6%” claim is a neural diagnostic on a **fixed 256-pattern balanced subset**: one duplicated detector pattern had conflicting logical labels, making the deterministic subset ceiling 255/256 = 99.61%; an MLP reached that ceiling on that same subset. It is not held-out logical success under the full circuit noise distribution. The tested CNN reached 254/256 on the same subset; later Q-SHIFT development reports say the CNN remained worse than PyMatching.
2. “99.99995%” is not comparable to Q-SHIFT logical correction success. A current primary arXiv report associates that number with Kerr-cat **QND bit-flip probability per readout measurement** (about 5×10⁻⁷), a physical measurement metric, not multi-round logical decoding. It must not be cited as a decoder benchmark. [Hazanov et al., arXiv:2611.04868](https://arxiv.org/abs/2611.04868)
3. The working Q-SHIFT circuit in the examined development lineage is a distance-3 rotated Z-memory, five rounds, 40 detector bits and one logical observable, with gate and measurement probabilities 0.003. The burst prototype injects a simultaneous `X8 X10` event after each of five `MR` boundaries; event draws are independent across rounds. The burst is a synthetic proxy, not measured hardware crosstalk.
4. Correlation-aware PyMatching is applicable to DEMs carrying decomposable separator metadata, and the Q-SHIFT v2 Pilot 1/2 explicitly sets the flag at **both construction and decode time**. Historical Stage 4 code built a correlation-enabled matcher but omitted the decode-time keyword, whose PyMatching 2.4.0 default is `False`; interpret those historical figures as ordinary decoding unless a saved execution record establishes otherwise. The Phase 3A preflight and PR #1 V1/V2 shared decoder path also construct with correlation support but omit the decode-time keyword; their reported matching outputs therefore used ordinary decoding. In the selected graphlike two-detector burst preflight, its `enable_correlations=True/False` constructor comparison is not a valid test of correlated decoding, because both calls to `decode_batch` default to `False`. A burst-aware graph/probability model is a separate intervention from the correlation decode switch.
5. Exact categorical MAP has already been implemented and validated for two small toy circuits. The full distance-3, five-round categorical circuit has 209 independent categorical locations (2^609 assignments), so brute-force exact enumeration is infeasible. A tensor-network or structured factor-graph approximation is plausible research, but no full-circuit exact reference has been established. True-p matching is privileged parameter knowledge, not an optimality bound.
6. The latest adaptive Q-SHIFT Pilot 2 is a bounded development no-go for the planned 11.736M-shot study: its frozen decision rule did not pass both required LER comparisons. The event controller showed operational savings in online CPU/switches, but all-in calibration accounting reversed the CPU comparison over the pilot horizon. Do not revive the large study without a new reviewed protocol and explicit owner scope/budget.
7. **Recommendation:** do not begin a new decoder experiment or sampling now. Preserve the code and prior reports. The next scientifically useful candidate is a tightly scoped, paired development comparison of a causal detector-only burst-aware update policy against the strongest pooled burst-aware static PyMatching and the existing EWMA/trailing baselines, with ordinary/correlation-aware decode explicitly separated. The study is only a protocol draft here; supervisor review and a separate explicit owner approval for a specified sampling scope and budget must come first.

## Verified Q-SHIFT system and decoder baseline

### Code and noise model

- Main circuit family: Stim rotated surface-code Z-memory; distance 3; five syndrome rounds; 40 detectors; one logical observable.
- Native Phase 2B noise: categorical `PAULI_CHANNEL_1` and `PAULI_CHANNEL_2` events at gate injection sites, measurement flips, and bias ratios including 10:1:1 / balanced / 1:1:10; typical gate and measurement probabilities are 0.003. The two-qubit categorical draw is one mutually exclusive joint event, not two independent flips.
- DEM conversion in the source examined: `decompose_errors=True, approximate_disjoint_errors=True`. This is a decoder-model approximation for categorical alternatives. It does not alter Stim sampling, but it does mean exact inference on the DEM is not exact inference on the circuit distribution.
- The burst extension adds `CORRELATED_ERROR(p) X8 X10` at five round boundaries. The parameterized PR candidate uses `p ∈ {0, .004, .008, .012, .016}`. The joint event is graphlike for the selected pair; broader pair scans in the prior preflight found 9/36 locations not graph-decomposable under the chosen matching interface.
- Existing Q-SHIFT adaptation estimates a scalar burst probability from 45 detector-only features (40 detector bits plus five nominated pair co-firing bits), using simulation profiles and a grid. It is a profile distance estimator, not a full syndrome likelihood estimator. The causal pilot applies estimates to future blocks and caches graph banks.

Correlated matching is a two-pass method that exploits **decomposable** correlated mechanisms retained in the DEM; it is not a generic exact hypergraph/MAP solver. The selected `X8 X10` burst produces two-detector graphlike events. The preflight's 256-shot constructor on/off comparison did not exercise the correlation-aware decode pass, so its identical predictions are not evidence that the decoder flag is neutral here. The valid Q-SHIFT Pilot 1/2 and correlation-pilot paths do set both flags. The burst-inclusive edge/probability model remains a separate treatment; report the corrected explicit correlation decode ablation only after a new, correctly wired comparison.

For the independently saved earlier categorical-decoder pilot (whose runners set both flags at construction and decode time), the development audit reports 1,343/720,000 pooled-fixed prediction disagreements between ordinary and correlation-aware decoding. Its equal-stratum correlated-minus-ordinary LER was -0.00025417 with root-cluster 95% interval [-0.00035000, -0.00016250]. These are reported prior development outcomes, not newly replayed, and an exploratory same-basis/bias pattern remains post hoc. This valid earlier comparison supports that the mode can matter, while the preflight and PR source findings show why exact call-site verification is essential.

### Source of “99.6%” and “99.99995%”

`outputs/neural_decoder_diagnostic/root_cause_analysis/ROOT_CAUSE_REPORT.md` identifies the 99.6% value: a 256-example deterministic subset had 128 examples in each label class, and one detector pattern appeared with conflicting labels, making the deterministic ceiling 255/256. A MLP reached 255/256 on that same subset. This is not a full fresh-noise test set, not a logical correction rate across the circuit distribution, and not an independently confirmed result.

The `99.99995%` value is associated in the cited primary preprint with QND measurement of Kerr-cat qubits, i.e. a per-readout bit-flip metric. It differs in physical system, denominator, task, and decoder status. A superficially similar number cannot be used as a Q-SHIFT baseline.

## Exact-reference feasibility and result

Prior Q-SHIFT work already provides an exact posterior enumerator for independent categorical fault locations. For each syndrome it accumulates joint mass `P(s,l)`, chooses the largest-mass logical class, and sums errors for exact toy risk. The toys have 3 data qubits and 2 detectors: three 4-outcome single-qubit locations (64 configurations), and two 16-outcome neighboring two-qubit locations (256 configurations). Independent parity-mask calculations and deterministic forced-outcome Stim checks matched for all 320 configurations. The 8-test unit suite was rerun here and passed in 0.351 seconds (Python environment reports Stim 1.16.0 and PyMatching 2.4.0 in its recorded toy result file).

On the asymmetric two-location toy, exact categorical MAP risk is 0.0600; both ordinary and correlation-aware PyMatching built from the approximate DEM choose a different logical class for syndrome `11` and have exact-channel risk 0.1128. In the one-qubit toy, both PyMatching modes agree with the exact decisions and exact risk 0.002646. This is a useful correctness/approximation witness, not an estimate of Q-SHIFT's full-code performance.

The existing feasibility report says the full distance-3, five-round categorical circuit has 209 independent categorical locations and `2^609` complete fault assignments. Direct enumeration is infeasible. Tensor-network decoding or structured factor-graph elimination may approximate MAP/posterior risk, but correlated categorical factors and repeated rounds can cause large contraction width. Therefore: (a) exact toy reference is available; (b) full-circuit exact decoder is not currently feasible by brute force; (c) no unconditional upper-bound claim is justified; (d) true-p matching is an oracle on parameter knowledge only.

## Candidate feasibility and novelty

| Candidate | Q-SHIFT fit | Cost / risk | Phase 1 judgment |
|---|---|---|---|
| A. Correlation-aware matching / explicit burst mechanisms | Strong fit for detector mechanisms that decompose to valid graph edges; informative for the existing pair burst. | Still a graphlike approximation; higher-order events can fail decomposition. Correlation flag can be neutral or harmful in some conditions. | Keep as a model-structure arm; prioritize burst-aware static graph before calling online adaptation a decoder gain. |
| B. PyMatching + residual correction | Existing geometry-preserving residual CNN exists. | Existing CNN/MLP diagnostics do not beat the strong matching/profile baseline; thresholding can harm and adds training/model-selection budgets. | Defer until the baseline and signal of residual errors are revalidated on new approved development data. |
| C. Structure-aware GNN / temporal CNN, RNN, transformer | Can consume full detector graph/history and represent syndrome context lost by scalar feature pooling. | Training data, compute, latency, calibration leakage, and distribution shift; much of this literature assumes larger code families or hardware data. A 40-bit, five-round code provides a limited scale test. | Do not build a larger network before proving residual headroom against correlation-aware fixed matching. |
| D. Hybrid inference | Latent burst-state posterior + cached matching/decoder confidence could help during genuine drift. | Latent-state identifiability and online causal likelihood are unresolved; model mismatch may dominate; decoder updates need validated complete graph/metadata, not ad-hoc edge edits. | Plausible later, after causal estimator diagnostics and the strong static comparator are frozen. |
| Exact / approximate MAP reference | Toy exact MAP available; tensor network has literature precedent for surface codes. | Full current circuit brute-force is exponential; approximate contraction's complexity depends on graph width and bond dimension. | Use toy exact as unit oracle; investigate a restricted factorized reference separately, and label all approximations. |
| BP+OSD / belief-matching | Strong known decoder families for richer parity-check/hypergraph representations. | Mapping categorical mechanism likelihoods to factor graph and maintaining fair cost comparisons requires extra work. | Candidate baseline in later headroom study, not a Phase 1 implementation. |

Adaptive syndrome-only estimation is established prior art, including sliding-window estimators and decoder-weight adaptation. The defensible research contribution is not “first adaptive decoder”; it would need to establish a useful operating envelope or a distinct decision policy under equal information, latency, update, and compute budgets, including drift and mismatch. See `LITERATURE_MATRIX.md`.

## Prior-art and research novelty conclusion

Primary sources directly overlap with each main idea: adaptive matching under drift (Spitz et al. 2018; Huo & Li 2017; Bhardwaj et al. 2026); graph reweighting for drift/correlations (DGR, 2023 preprint); experimental and model-informed matching weights; correlated/hypergraph inference through belief-matching; tensor-network approximate MAP; GNN and recurrent-transformer decoders; hardware-side RL adaptation. The broad approach is not novel by itself. A prospective claim should be narrower: a fair, causal, cache-aware comparison of change-triggered updates against strong fixed, trailing-window, EWMA and periodic policies under abrupt and smooth drift, bursts, and deliberately mismatched observation models. It should report where adaptation fails as well as where it helps.

## Proposed first experiment and resource envelope

See `NEXT_EXPERIMENT_DRAFT.md`. It is explicitly **not frozen and not authorized**. Keep development-only, new independent seeds, identical chronological detector streams, and shared decoder-cache opportunities. Make the primary comparison event-triggered causal policy minus pooled detector-calibrated burst-aware static matching; retain nominal p=0, batch Q-SHIFT, trailing, EWMA, periodic, and privileged true-p as separate interpretable arms. Evaluate ordinary and explicit correlation-aware decoding as paired, separately reported modes. The oracle is diagnostic only. Do not mix true p or labels into controller decisions.

Use pilot-scale total shots no larger than 300,000 unique shots for an initial reviewable stage, with a hard CPU wall budget of 1 hour and RSS ceiling of 2 GiB, unless the owner approves a different scope after reviewing this draft. A proposed split is no training set; 60,000 detector-only template shots; 20 independent chronological development streams per scenario; 1,000 warm-up/calibration shots and 1,000 scored shots per stream. Five scenarios implies 100,000 scored plus 100,000 warm-up shots; templates bring total to 260,000. Reserve model-selection/tuning data within development-only streams and do not reuse scored stream labels for controller tuning. This is a budget proposal only; no seeds or freeze have been created. Before any run, explicitly resolve whether the owner wants this 260,000-shot scope and define no-harm/practical-benefit decision thresholds with an independent supervisor.
