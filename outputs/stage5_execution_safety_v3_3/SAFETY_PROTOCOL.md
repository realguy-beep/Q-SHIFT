# Stage 5 Execution Safety Repair v3 — Benchmark Protocol

This version changes orchestration, checkpoint durability, recovery bookkeeping, source-freeze enforcement, and independent artifact verification only. It delegates circuit construction, noise, decoder arms, calibration, estimands, allocation, and inference to the frozen Stage 5 v2 runner and configuration. It cannot change the 6,050 roots, 27,225,000-shot allocation, or Endpoint B rule. It supersedes safety v3.2 after review found that the launcher also needed to enforce its own source/config freeze at each preflight and run.

No Stage 5 samples are authorized or generated by this safety validation. The frozen v2 manifest is verified by SHA-256 before benchmark runs. The new safety source, tests, benchmark configurations, and seed inventory are frozen before any benchmark sampling.

## Safety design

- A persistent launcher lock and a separate worker lock are protected by nonblocking OS file locks (`msvcrt.locking` on Windows, `flock` on POSIX). Contention fails immediately. The worker holds its lock for the full sampling/aggregation lifetime, so a surviving child remains protected if the launcher dies. A stale owner record is only accepted after the kernel lock can be acquired and the recorded PID is not alive; ambiguous live-PID metadata fails closed.
- The launcher process owns the wall-clock deadline and supervises the sampling worker, independent auditor, and finalizer child. Frozen v2 `completed` writes are translated to `finalizing`. The finalizer may write `completed` only after saved-array audit, count checks, and final manifests pass within a reserved deadline margin. Parent timeouts terminate each child and record deadline status; expiry during final artifact work never becomes a passing completion.
- NPZ checkpoints are written to unique same-directory temporary files, flushed and fsynced, atomically replaced, then accompanied by a SHA-256 commit marker. A missing or mismatched marker is uncommitted/corrupt and blocks resume.
- Status, summaries, archive manifests, recovery journals, and finalization manifests use atomic replacement. POSIX directory fsync is attempted. Windows does not expose the same portable directory-fsync operation through this implementation; process-crash atomicity is tested, but sudden power-loss persistence is a limitation.
- An in-flight sampler stream is never counted as completed unless its durable checkpoint and hash marker exist. Recovery requires an explicit flag. If no checkpoint exists, the frozen stream may be replayed with its same deterministic seed; its count is committed only once. An archive with an invalid/missing marker is never replayed or overwritten automatically.

## Benchmark-only allocations

The checked-in test allocations use a separate high-range benchmark namespace and the single nonzero condition p=0.004. The ordinary paired fixture uses two roots, 256 calibration shots and 512 evaluation shots per root (1,536 total). Additional disjoint seeds are reserved for write-boundary and interruption fixtures. A separate 1,000,000-shot calibration fixture is used only to terminate a live Stim sampler call; it has no logical-performance use. The seed inventory is checked against recoverable nonsealed historical seed metadata and records counts/collision outcomes without listing sealed Stage 5 seed values.

The benchmark worker uses the frozen v2 implementation with only a test-only output path, sample counts, condition/root allocation, benchmark seed map, and benchmark summary adapter. It never targets `outputs/stage5_secondary_inference_repair_v1/run`.

## Acceptance criteria

1. Two live processes cannot own the same run directory; a crashed process releases the OS lock and leaves a detectable stale owner record.
2. A completed checkpoint has a readable NPZ, matching SHA-256 commit marker, expected root identity, and independently redecoded predictions.
3. Crashes before NPZ replacement or between replacement and commit marker do not appear completed and fail closed.
4. Crashes after commit marker but before status update resume from the committed checkpoint without resampling its stream.
5. Crashes after a Stim sampler returns but before its checkpoint leave the stream in-flight and uncommitted; explicit recovery replays the same fixed seed and the final audit counts the stream once.
6. Parent deadline expiry during aggregation or artifact writing prevents a completed status.
7. All benchmark results pass independent saved-array reconstruction. The Stage 5 run path remains absent and frozen hashes remain unchanged.
