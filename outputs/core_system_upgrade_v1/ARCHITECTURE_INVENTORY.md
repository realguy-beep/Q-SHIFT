## Changes made in this upgrade

1. qshift_core_v1/ introduces typed decoder metadata, detector-only input contracts, explicit [shots, observables] output, a PyMatching adapter, a decoder registry, a causal fallback selector, domain-separated seed helpers, and a paired evaluation-record utility.
2. dashboard/simulator.py keeps the existing one-observable one-dimensional compatibility result, but delegates input/output validation to the adapter. The old Phase 2B bank’s constructor correlation setting and decode setting are both explicitly true.
3. dashboard/configuration.py rejects coercive or non-finite values and validates Stim seed bounds before allocation.
4. The current page states that configured noise is not inferred hardware noise, and that a decoder output is an observable prediction rather than a physical correction map.

## Safety boundary

The new paired evaluator accepts caller-supplied development or held-out-development arrays only. It refuses a protected-test scope. It has no sampling, file-discovery, training, or protected-data access code. The new controller’s API accepts an estimate and a proposal without any observable-label or hidden-regime argument; causal block provenance is checked before a switch. These are API safeguards, not proof that upstream callers did not misuse labels; independent audit and source review remain necessary for any future experiment.
