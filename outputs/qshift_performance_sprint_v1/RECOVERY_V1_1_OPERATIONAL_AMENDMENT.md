# V1.1 Operational Recovery Amendment

**Scope:** repair the paired-evaluator decoder-name mismatch only; preserve the original V1 freeze and failed attempt.

The original V1 run stopped after 56 sampler calls. Training detector rows (5,000) and 50 calibration detector archives (25,000) are present and hash-inventoried. The first evaluation call used the frozen p=0/root-0 seed and returned 2,000 rows, then the evaluator rejected the profile decoder because its metadata name was profile_p0_r00 while the registration key was profile_estimated. The failure happened before any decoder invocation, prediction, label scoring, or evaluation archive write.

The original samples/status.json reports 32,000 verified shots, but only 30,000 rows are persisted as training/calibration archives. That status counter is overstated by the uncommitted 2,000-row evaluation call. Preserve the original status and files unchanged; the recovery runner relies on the explicit input inventory and archive checks, not that counter.

V1.1 changes only the per-root profile decoder metadata name to the fixed evaluator key profile_estimated and writes all recovery evaluation archives under samples/recovery_v1_1/. It reads and verifies the original training/calibration arrays and original V1 source manifest without rewriting them. It does not change the estimator, circuits, probabilities, DEM flags, decoder modes, allocation of unique sample IDs, statistical procedures, or success gate.

The failed call's arrays were not persisted. V1.1 replays that same p=0/root-0 seed, on the same frozen circuit and Stim 1.16.0, to reproduce the uncommitted partition, then executes the remaining 49 evaluation partitions using their original seeds. The replay is recorded as a repeated sampler invocation with the same partition identity, not as an additional unique sample. No new seed is allocated. Because the failed call's bytes were not persisted, bit-for-bit comparison to its lost in-memory arrays is impossible; deterministic replay under the same Stim version, circuit bytes, and seed is the recovery assumption and is explicitly a residual limitation.

Operational call count for the combined attempts is 106 (56 failed-attempt calls plus 50 recovery calls). Stim returned 132,000 rows across both attempts because the failed p=0/root-0 call was replayed. The final archive set contains exactly 130,000 unique partition rows (5,000 training, 25,000 calibration, 100,000 evaluation). The original V1 105-call cap is superseded only for this recovery by a one-call replay allowance; no other extra calls or seed substitutions are allowed.

The initial failed status, first-run start metadata, training array, calibration arrays, and calibration estimator record remain preserved. Recovery has a distinct source manifest, status, output subdirectory, and audit report. If the source hashes, input archive hashes, expected incomplete state, seed mapping, resource limits, or unique-root checks differ from this record, stop without sampling. If any further interruption occurs, preserve it and request a new decision; no automatic retry.

Before sampling, a prevalidation candidate source manifest (SHA-256 `de42ec6ae4badfdbec22ab1617d18d39351ba53a42c4dec14a1cc6dbfb4af7d5`) was generated. A deterministic test exposed an incorrect expected source-file count (the freeze list contains nine entries). That candidate was preserved under `RECOVERY_SOURCE_MANIFEST_V1_1_PREVALIDATION.json`, marked superseded, and was never used to authorize or run sampling. The final pre-run manifest must bind the corrected tests and all recovery code.
