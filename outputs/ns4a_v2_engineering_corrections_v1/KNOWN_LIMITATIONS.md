# NS-4A V2 Engineering Corrections — Limitations

## Supervisor

- The monotonic deadline is checked around process waits, Job membership
  queries, drain polling, and cleanup. A synchronous Windows API call that
  itself never returns cannot be pre-empted by this Python process. If such a
  call eventually returns after the deadline, this supervisor fails closed.
  Strict hard-real-time enforcement against a hung OS call would require a
  separate external watchdog.
- Synchronous filesystem operations have the same limitation. The V2 child is
  subject to Job termination at the deadline while the supervisor is
  responsive, but the supervisor cannot asynchronously interrupt a blocked
  filesystem operation in its own status persistence.
- Atomic temp-file plus replace protects against exposing a partially written
  supervisor status file. It does not prove directory-entry durability after
  power loss. The V2 checkpoint/archive implementation fsyncs file contents
  before replacement, but Windows directory-metadata durability under abrupt
  power loss is not established here.
- Terminating the child during a sampler or archive transaction can leave a
  partial/uncommitted root. The supervisor does not repair, retry, or resume
  that state; the existing V2 exact-seed and archive/commit-marker recovery
  audit must be applied. Ambiguity means stop.
- The Job Object retains kill-on-close and tracks descendants that remain in
  the Job. The tests exercise ordinary Python child creation. They do not prove
  behavior for every third-party process that might explicitly request Job
  breakaway or for nested Job configurations unavailable in the tested
  environment.
- This package has not been wired into the V2 runner, authorization path, or
  production command. No real V2 run has been attempted.

## Memory metric

- The metric is one process's PeakWorkingSetSize high-water value, paired with
  the current WorkingSetSize snapshot. It is not process-tree aggregate memory,
  virtual memory, private bytes, or total machine RAM.
- No hard Job Object memory cap is set. Job Object's PeakJobMemoryUsed is not
  enabled or used as an aggregate enforcement mechanism.
- The V2 config field is still named peak_rss_bytes. This package does not
  edit that frozen file. Its value is interpreted only in a future
  versioned integration as the existing 2-GiB numeric limit applied to the
  explicitly named Windows process-peak-working-set metric; a source/schema
  update and separate identity approval are required first.
- PSAPI measurement errors, invalid handles, malformed structure size,
  zero/inconsistent values, and unsupported operating systems fail closed.
  There is no fallback to current RSS, virtual memory, system RAM, or a weaker
  metric.
- The live Windows check compared PSAPI's earlier high-water reading against
  PowerShell/.NET Get-Process for the same process. The later external value
  was greater, as expected when measurements occur at different instants; the
  numbers are diagnostic evidence, not workload capacity evidence.

## Historical evidence

- The five readiness reports remain unchanged. The existing readiness
  decision is still CORRECTIONS_REQUIRED; this package closes only the
  supervisor and Windows memory-measurement engineering items.
- The V6 benchmark report is not available in this checkout for fresh
  re-verification. Its prior extracted measurements remain qualified as
  previously observed only.
- V6/V7 preservation testing compared read-only file inventories before and
  after a synthetic fixture run. The clean branch worktree has 13 visible V6
  files (58,094 bytes), versus the prior V7 report's 34-file / 162,841-byte
  inventory. The earlier full inventory was not reconstructed here. The
  V7 directory also contains one ignored Python bytecode cache generated by
  the read-only V7 test run; source and tracked evidence were unchanged. The
  attempted cleanup of that exact generated cache was rejected by local
  command policy, so it remains outside the commit.
- Historical outcome-exposure and influence limitations, seed-allocation
  blockers, statistical limitations, and missing independent historical
  provenance are not addressed here.
